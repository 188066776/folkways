# Superb Warfare

[玩法](gameplay.md) · [战斗架构](combat-architecture.md) · [English](../en/warfare.md)

将 `folkways_warfare` 与 Core、Vanilla、Superb Warfare **0.8.9.2**、Kotlin for
Forge **5.12.0** 一起安装。两个原生依赖均在 `blockwright.toml` 中固定 SHA-512。
可选 `warfare` 配置会一起安装它们。本模块不依赖 RTS。

## 装备档案

打开聚落书的**配装**页面，新建档案，将支持的枪械添加为武器条目。
物品提供器根据弹匣和射击周期预填可编辑的弹药补给。设置**目标数量**和
**低于此量时补给**，分配给居民，并在收集位置 32 格内的登记仓库存入真实武器和弹药。

| 枪械     | 弹药     | 有效射程 |
| -------- | -------- | -------- |
| Glock 17 | 手枪弹药 | 24 格    |
| MP5      | 手枪弹药 | 32 格    |
| AK-47    | 步枪弹药 | 48 格    |
| M4       | 步枪弹药 | 48 格    |
| M870     | 霰弹弹药 | 20 格    |
| SVD      | 狙击弹药 | 64 格    |

数量由档案决定，没有全局十六发配额。严格补充阈值、分批补满、仓库权限、预留和组件匹配
沿用 Vanilla 的物流。职业工具清单不负责配置战斗装备。

居民借用真实枪械到主手，通过 `GunData.shoot` 射击。优先消耗已装填弹药，空弹匣再借入
一发真实散装弹药；已装填弹药计入档案库存。原生热量和枪机状态随真实物品更新，归还背包
不能重置 RPM 或泵动周期。弹体插入被拒绝时退还原来的散装弹药，保留组件和名称。

战斗会话将枪械借到居民真实主手期间，皮肤居民采用 SBW 原生第三人称双臂持枪姿势，
并跟随头部瞄准；归还背包后清除姿势。这与 TACZ 居民使用相同的装备同步来源。
举枪本身不代表某次射击已通过服务端的视线、弹药和友军安全检查。

只接受六种可预测的枪械配置。特性、属性覆盖、爆炸或穿甲效果、自定义弹体、自动装填和
不支持的弹药消耗配置会被拒绝。持枪后改成不安全配置，会在发射前关闭会话。
手持直射仍检查敌对关系、射程、自身视线和友军通道。

## 独立武器站与炮弹补给

1. 放置并解锁支持的固定武器，在 SBW 中选择普通迫击炮弹或炮的 **HE** 弹种。
   AP 和 TOW 不参加自动操作。
2. 手持聚落书，在单点／成员纳入模式下靠近到八格内，指向炮的实体并将其明确纳入为
   **独立武器站**。实际炮体外需要可步行到达的通路与安全站位。绘制包含炮的哨区不会纳入或派驻炮位。
3. 为战斗居民分配配装。任意已分配配装都可操作武器站，包括近战或只有补给条目的配装。
4. 将炮弹添加为**补给**条目。迫击炮选择 `superbwarfare:mortar_shell`，再设置目标数量
   和补充阈值；Mk42 HE 选择 `superbwarfare:large_shell_he`。固定组件的条目只收集对应变体。
5. 分配配装并为登记仓库补货。每台已纳入武器自动补一名空闲战斗居民，不必逐炮选配装或指定居民。
   有效现任成员保留；缺员时先补武器站，再补哨区／路线，同级按 UUID 排序。
   操作员通过正常物流收集自己配装指定的炮弹，没有隐藏额度。

独立炮位接受迫击炮、Mk42、BL132、Mle1934、静止的 FH77BW 榴弹炮和 HPJ11；
真正操作时仍要求已知安全 HE 炮弹配置。坦克、飞机、船只、移动载具、制导 TOW、AP、燃烧、集束和未知
弹体均排除。已有乘员保留座位。Vanilla 只为该炮自动选出的有效操作员授予独占租约。迫击炮旁站操作；
其他武器使用原生炮塔座位，包括 FH77BW 的第二座位。

操作员通过正常寻路步行到炮体外侧。完整居民碰撞箱必须能站下，不与炮或其他阻挡实体相交；
候选只取紧邻炮体外侧的一圈，包含角格；最近脚点走不到时，会尝试其他可达候选。
到达即登炮，无须等待敌人，也不再检查眼睛到碰撞箱的交互距离。所有通路封闭时显示原有无法到达反馈，保留操作员名额；
清理通路与站位后可再次尝试。迫击炮仍在炮旁原生操作，不占乘员座位。

迫击炮和 FH77BW 声明间接射击，可以使用其他防御居民或巡逻员写入的殖民地
`SpottedTargets` 新鲜观察，在操作员视野之外开火。瞄准固定的观察位置；目标死亡、卸载、
失去敌对关系、观察过期或偏移超过两格即失效。Mk42 等直射武器需要自己的射线。
武器站不独立扫描隐藏目标，也不追击。

仍使用 SBW 原生载具开火接口和迫击炮延迟。准备阶段不会在两次 tick 之间把弹药副本留在
武器中。真实发射时，Vanilla 重新检查同一租约、职责、观察、射程与直射条件；集成检查
实际炮口方向、完整弹道、散布和预计落点。实体保护半径为配置爆炸半径的**两倍**；方块
保护单独使用 SBW 最大扁平破坏半径，即配置值的 **0.6 倍**。两者都加入散布余量。
友军、宠物、玩家或自家殖民地方块、仓库面临风险时停火；未知或未加载弹道也会被拒绝。

发射前从背包预留一发匹配的真实炮弹，弹体成功加入世界后才消耗，拒绝则退回。
临时借入的原生弹药状态在 `finally` 中恢复。切换目标、过期观察或准备期间进入落点的
友军都不能借用旧队列的授权。**哨位**总览显示射线受阻、缺少弹药、武器站不可用、占用、直接指挥暂停和无安全站位。
**撤出武器站**可在炮卸载时撤销纳入、操作员名额和租约。同格另一门炮不能继承原炮 UUID 的配置。

撤退或其他已验证的直接命令、撤岗、档案失效、撤销巡逻许可、死亡、卸载、武器站或哨区
移除、殖民地关闭，都会释放职责及其座位。无效命令保留当前座位。Vanilla 保存临时座位
身份，租约和待发射请求不保存。崩溃或快照恢复后的孤立标记只释放记录的座位，不影响无关
骑乘。恢复的带标记迫击炮准备会取消。已发射弹体继续遵循 SBW 物理。

旧存档不会自动纳入仅被哨区包含的武器。旧哨区槽位转成允许配装并集和总人数，指定居民丢弃。
已有武器站保留纳入并自动补员，旧逐炮配装岗位配置丢弃。运行中的租约和待发射请求不恢复。

## 观察器材

在**配装**页面选择**＋ 添加 → 观察器材**并选原版望远镜，即可添加目标数量／补给阈值为 1/1
的普通补给条目。居民必须同时满足档案要求和背包内真实持有匹配物品，才得到视野加成。
缺少望远镜沿用装备缺项与仓库缺货显示，并从登记仓库收集。只分配档案没有加成，多件不叠加。

视野按观察者与目标成对计算，系数均位于服务端 `sentries` 配置：
`defenderSightRadius` 基准 **32**，加警觉技能；观察者眼睛每比目标眼睛高一格，再加
`sightHeightPerBlock` **1.5** 格，最多计算 `sightHeightLimit` **16** 格高度差。
低于目标不加成，也不额外惩罚；无需查询周边地面。

随后乘以目标亮度系数：有效亮度不高于 `darkSightLightLevel` **4** 时为
`darkSightMultiplier` **0.25**，在 `fullSightLightLevel` **12** 时线性增至 1。
低光阈值始终规范化为低于完整亮度阈值；设为 0 可恢复旧插值方式。使用原版有效亮度，包含方块光和受时间、雨雷
削减的天空光。观察者夜视、目标着火／Glowing 或原生发光生物豁免黑暗惩罚。
数据包标签 `folkways:luminous_targets` 默认包括烈焰人、发光鱿鱼、岩浆怪，可扩展。

只有背包实持配装要求的观察物品，才把高度／光照调整后的距离乘以
`observationSightMultiplier` **2**，只乘一次。结果限制在 `minimumSightRadius` **3** 与
`maximumSightRadius` **128** 之间；最低近距不穿墙，总上限也限制扫描。配置上限低于下限时，
以上限为准。倍率设为 1 可关闭放大；原固定加法配置 `observationSightBonus` 已移除，不自动换算旧值。

无警觉技能时，默认白天平地 32 格，八格眼高优势为 44 格，该城墙上携望远镜为 88 格
（平地望远镜为 64 格）；有效亮度 0–4，包括原版夜间天空，无望远镜平地为 8 格。
其余系数保持不变；最大可能扫描／圆环为无望远镜 56、有望远镜 112，仍受 128 硬上限约束。
旧存档保留已写入的基准值，须显式把服务器配置设为 32 才采用新默认。

只影响发现距离，不改变武器射程；侦察员、迫击炮与 FH77BW 前观仍通过共享目击工作。
物品、效果或照明变化影响下一次检查，已有真实报告继续遵循原 TTL 与位移失效规则。
哨位圆环表示观察者的最大可能视野，并不保证发现圈内所有目标。

当前固定的 SBW 0.8.9.2 没有独立双筒望远镜物品；只有已安装版本实际注册
`superbwarfare:binoculars` 或 `superbwarfare:spyglass` 时，才会将其列为可选，不生成缺失物品。

## 爆炸保护与验证

自动发射检查生物破坏权限。居民弹体爆炸前再次检查权限和落点安全，在任何伤害或破坏前
触发可取消的 NeoForge `ExplosionEvent.Start`，且不会重复触发。每一层原生方块破坏候选
先经过 `ExplosionEvent.Detonate`，SBW 的实体 Detonate 处理也保留。
这些补丁只处理居民射击，玩家操作仍沿用原生行为。

`Weapons.register` 提供真实执行，`LoadoutRegistry.register` 提供物品使用元数据，
`WeaponStations.register` 发现稳定的武器站对象，独立岗位按明确纳入的实体 UUID 筛选。
普通哨区不会获取炮位。Vanilla 管理租约、延迟发射事务、
档案物流和持久化临时座位。Vanilla 与 Warfare 都不导入 RTS；可选 RTS 识别 Vanilla
持有的座位，并在完整命令验证之后释放。

验证命令见[测试](testing.md)。专用 GameTest 覆盖原生射击、有限弹匣和补给、射速、
不安全变体、巡逻共享观察、落点停火、延迟取消、炮弹物流、座位生命周期、快照释放和
爆炸事件。静态设计审核与服务端测试不代表真实客户端玩法验收。
运行 `npm run visual:take -- weapon-poses.spec.ts --workers=1` 可获取 AK-47／M870
皮肤居民与 TACZ M4A1 的对比截图，并检查原生双臂旋转与会话释放。哨区卡、其他外观后端
和每种固定武器的客户端检查仍是独立工作。
